# Файл копии `homensai-rent-archive/1`

Источник: Rent `app/archive/pack.py` (сборка `build_archive`, чтение `open_archive` → `_open_outer` → `_check_inner`),
`app/archive/domain.py` (имена), `app/archive/keys.py` (конверт), `scripts/migrate.py` (служебный бэкап). Вектора —
`vectors/archive.json`.

## 1. Имя и размещение

- Имя: `ГГГГ-ММ-ДД_HomensaiRent_Archive.zip` (латиница), дата — день копии.
- На носителе: `HomensaiRent/Копии/ГГГГ/ММ/<имя>`; рядом `HomensaiRent/Копии/chain/NNNNNN.json` — манифесты цепочки
  (`chain.md`).
- В Telegram файл больше 50 000 000 байт режется на части `<имя>.001`, `<имя>.002`, … — **простое побайтовое деление**
  (склейка — конкатенация по номеру). Подпись каждой части несёт sha256 целого файла. Конверт ключа читается из хвоста
  последней части (конец ZIP — в ней).

## 2. Внешний ZIP

Ровно **один** член: `archive.zip` (внутренний ZIP, см. § 4). Имена с фамилиями снаружи не видны. Метод хранения члена —
STORED (внутренний ZIP уже сжат). Режим определяется **комментарием ZIP** (запись конца каталога, EOCD):

| Режим защиты (`archive.protection.mode`) | Комментарий | Член `archive.zip` | Пароль ZIP |
|---|---|---|---|
| `env` (прежний) | пустой (нет префикса `HRKEY1 `) | WinZip AE-2, AES-256 | `BACKUP_PASSWORD` (UTF-8, ≥ 16 знаков при создании) |
| `generated`, `custom`, `pin` | `HRKEY1 {json}` (`key-envelope.md`) | WinZip AE-2, AES-256 | секрет копии — 44 знака ASCII (base64url 32 случайных байт) |
| `none` | `HRKEY1 {"v":1,"mode":"none"}` | не зашифрован | — |

### 2.1 WinZip AE-2 (как пишет pyzipper 0.4.0 с `setencryption(WZ_AES, nbits=256)`)

Спецификация формата — WinZip «AES Encryption Information: Encryption Specification AE-1 and AE-2».

- Заголовок члена: флаг бита 0 (зашифрован) = 1; метод сжатия = **99**; CRC-32 = **0** (признак AE-2: CRC не пишется,
  целостность — только HMAC).
- Дополнительное поле `0x9901`, 7 байт: версия `0x0002` (AE-2, LE16), производитель `AE`, сила `0x03` (AES-256),
  настоящий метод сжатия (LE16; у копии Rent `0` = STORED, у служебного бэкапа `8` = DEFLATE).
- Данные члена: `соль (16 байт) ‖ проверочное значение пароля (2) ‖ шифротекст ‖ код аутентификации (10)`.
- Ключи: `PBKDF2-HMAC-SHA1(пароль, соль, 1000 итераций, 66 байт)` → `ключ AES (32) ‖ ключ HMAC (32) ‖ проверка (2)`.
- Шифр: AES-256-CTR, **128-битный счётчик little-endian, первый блок = 1**.
- Код аутентификации: первые 10 байт `HMAC-SHA1(ключ HMAC, шифротекст)`.
- Совпало проверочное значение, но не совпал HMAC — копия повреждена (`corrupt`); не совпало проверочное значение — неверный
  пароль (`bad_password`). Вероятность случайного совпадения 2 байт — 1/65 536, поэтому окончательное решение — HMAC.

Слабость формата (1000 итераций PBKDF2-SHA1) зафиксирована в `docs/CRYPTO.md`: в режимах с ключом хозяйства паролем ZIP
служит случайный 256-битный секрет, перебирать нечего; в режиме `env` требуется пароль не короче 16 знаков.

### 2.2 Пределы чтения (защита от ZIP-бомб и подложенных файлов)

| Проверка | Предел | Код |
|---|---|---|
| Записей во внешнем каталоге / размер каталога | 16 / 64 КиБ (по EOCD до разбора) | `corrupt` |
| Состав внешнего ZIP | ровно `["archive.zip"]` | `corrupt` |
| Копия «без пароля», но член зашифрован | — | `bad_password` |
| Размер файла, объявленный и фактический размер члена | `max(2 ГиБ, 20 × содержимое последней своей копии)`; снимается только подтверждением владельца при ручном восстановлении | `too_big` |
| Записей во внутреннем каталоге / размер каталога | 100 000 / 32 МиБ | `corrupt` |
| Комментарий с префиксом `HRKEY1 `, но JSON не разбирается или длиннее 65 535 байт | — | `corrupt` |

## 3. Комментарий-конверт

`HRKEY1 ` (7 байт ASCII, с пробелом) + канонический ASCII-JSON. Поля, кодировки и открытие — `key-envelope.md`, схема —
`schemas/key-envelope.schema.json`. Комментарий ZIP **не** защищён HMAC AE-2: подмена конверта обнаруживается иначе —
AEAD-расшифровкой секрета (неверный секрет не откроет член ZIP) и подписью манифеста цепочки над sha256 всего файла.

## 4. Внутренний ZIP `archive.zip`

Не шифруется. Члены (Rent пишет DEFLATE; в векторах — STORED ради воспроизводимости, читатель ДОЛЖЕН понимать оба):

| Путь | `kind` в манифесте | Что |
|---|---|---|
| `Export/HomensaiRent_Export_ГГГГ-ММ-ДД.xlsx` | `excel` | книга Excel с формулами |
| `Database/rent.sqlite3` | `database` | согласованный снимок SQLite (backup API), прошёл `integrity_check` и `foreign_key_check` |
| `Invoices/…` | `invoice` | PDF счетов и реестров выбранных месяцев |
| `Data/<storage_key>` | `data_file` | прочие зарегистрированные вложения хозяйства |
| `manifest.json` | — | манифест (последним членом) |

Время членов — время копии (не раньше 1980 года). Состав ZIP ДОЛЖЕН совпадать с `files[].path` ∪ {`manifest.json`}
без повторов; база ДОЛЖНА присутствовать.

## 5. Манифест `manifest.json`

UTF-8 JSON (`ensure_ascii=False`, отступ 1). Схема — `schemas/archive-manifest.schema.json`.

| Поле | Тип | Значение |
|---|---|---|
| `format` | строка | `homensai-rent-archive/1` |
| `created_at` | строка | UTC `ГГГГ-ММ-ДДTЧЧ:ММ:ССZ` |
| `on` | строка | дата копии `ГГГГ-ММ-ДД` |
| `rent_version` | строка | версия программы (`?`, если не прочитана) |
| `warnings` | строки | предупреждения сборки, без имён файлов |
| `file_scope` | строка | постоянный текст о составе вложений |
| `invoice_months` | строки `ГГГГ-ММ` | месяцы счетов в копии |
| `applied_migrations` | строки `модуль/NNNN_имя` | применённые миграции схемы по порядку (`common/…` — общие) |
| `content_fingerprint` | объект | `{counts: {таблица: число строк}, payments_minor: {валюта: сумма подтверждённых оплат в копейках}, audit_last: время последней записи журнала или null}` |
| `files` | массив | `{path, kind, size, sha256}` для каждого члена, кроме манифеста |

Манифест не подписан сам по себе: его целостность держится на HMAC AE-2 (ключ из пароля/секрета) и на подписи манифеста
цепочки над sha256 всего файла копии.

## 6. Порядок открытия и коды ошибок

1. Файл есть и читается — иначе `not_found` (нет файла или прав), `corrupt` (ошибка чтения существующего файла).
2. Каталог внешнего ZIP в пределах (§ 2.2) — `corrupt`.
3. Комментарий: нет `HRKEY1 ` → прежняя копия, нужен пароль архива (`no_password`, если не дан); `mode: none` → без
   пароля; иначе секрет копии из конверта по паролю/PIN/ключу восстановления (`key-envelope.md`): пусто — `no_key`,
   неверный пароль — `bad_password`, чужой ключ восстановления — `recovery_wrong`, опечатка в ключе — `recovery_checksum`,
   повреждённый конверт — `corrupt`.
4. Внешний ZIP: неверный пароль ZIP — `bad_password`; HMAC, состав, неизвестный метод — `corrupt`; предел — `too_big`.
5. Внутренний ZIP и манифест: разбор, `format`, состав — `corrupt`; sha256 или размер члена — `checksum`.
6. База (по умолчанию): `integrity_check` / `foreign_key_check` — `db_corrupt`; `content_fingerprint` не совпал — `fingerprint`.

Тексты кодов (RU/UK) — `error-codes.json` (выписка из `app/errorbook` Rent). Коды сборки копии: `no_password`,
`weak_password`, `db_missing`, `source_corrupt`, `build_failed`, `excel_failed`, `bad_protection`.

## 7. Служебный бэкап `homensai-rent-backup/1`

Перед миграцией, обновлением, откатом и раз в час Rent делает служебный бэкап (`scripts/migrate.py`): ZIP с членами
`rent.sqlite3` и `manifest.json` (оба DEFLATE), те же три режима защиты и тот же комментарий `HRKEY1` (AE-2 c паролем
`BACKUP_PASSWORD` или секретом копии; без пароля — открытый ZIP). Манифест: `format`, `created_at`, `reason`, `db_member`,
`sha256`, `size_bytes`, `applied_migrations`, `integrity` (`ok` / `not_checked`), `content_fingerprint`. Права файла в
Linux — 0600. Схема и вектора служебного бэкапа — **уточнить** (в этот выпуск спецификации не вошли).
