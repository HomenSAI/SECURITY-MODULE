# Конверт ключа копии `HRKEY1` и ключи восстановления

Источник: Rent `app/archive/keys.py`, `app/security/recovery.py`, `app/security/codes.py`, `app/security/shamir.py`,
`app/security/webauthn.py` (`prf_recovery_secret`). Решения владельца Rent 28.10-269/270/279/282/284. Вектора —
`vectors/identity.json`, `vectors/envelope.json`, `vectors/recovery.json`, `vectors/argon2id.json`. Схема —
`schemas/key-envelope.schema.json`.

## 1. Ключи

| Ключ | Что | Где хранится |
|---|---|---|
| Ключ хозяйства (identity) | пара X25519 (RFC 7748), закрытый 32 байта | открытый `pub` и `wrapped` — в настройке `archive.protection` и в конверте каждой копии; пароль/PIN нигде |
| Секрет копии | 32 случайных байта, записанные base64url (44 знака ASCII); эти 44 байта и есть пароль внешнего ZIP | только в конверте, запечатанным |
| Ключ восстановления | 16 случайных байт (128 бит) | на аварийном листе и в менеджере паролей; на ПК — только открытый ключ получателя |
| Получатель восстановления | пара X25519, закрытый = HKDF от ключа восстановления | на ПК — `public_key` и `sealed` |

Новая пара ключа хозяйства создаётся при включении пароля/PIN и при смене пароля; старые копии несут свой `wrapped` и
открываются прежним паролем.

## 2. Объект `wrapped` — закрытый ключ хозяйства под паролем или PIN

```
key   = Argon2id(password = UTF-8(пароль или PIN), salt = 16 случайных байт, length = 32,
                 memory_cost = m КиБ, iterations = t, lanes = p)            ; RFC 9106, версия 0x13
ct    = ChaCha20-Poly1305(key).encrypt(nonce = 12 случайных байт, plaintext = закрытый X25519 (32),
                 aad = "homensai-rent/archive-identity/1" ‖ pub (32 байта))  ; RFC 8439 → 48 байт
wrapped = {"v":1, "kdf":"argon2id", "m":…, "t":…, "p":…, "salt":b64url, "nonce":b64url, "ct":b64url}
```

- Параметры записи: пароль — `m=65536, t=3, p=4`; PIN — `m=65536, t=8, p=4`.
- Параметры чтения (из чужого файла): `19456 ≤ m ≤ 1048576`, `2 ≤ t ≤ 32`, `1 ≤ p ≤ 16`, `m ≥ 8p`; иначе `corrupt`
  (нижняя граница — минимум OWASP, верхняя — защита от подложенной копии, требующей гигабайты памяти).
- Пароль кодируется UTF-8 **без** NFKC-нормализации (в отличие от пароля входа, § 7) — **уточнить**, нужна ли
  нормализация для паролей копий.
- После расшифровки читатель ДОЛЖЕН проверить, что открытый ключ из полученного закрытого равен `pub`, иначе `corrupt`.
- Неверный тег AEAD — `bad_password`.
- Отпечаток ключа (`kid`): `"HR1-" + группы по 4 из первых 16 знаков HEX(SHA-256("homensai-rent/archive-key\x00" ‖ pub))`
  в верхнем регистре, например `HR1-7E9C-9C11-7760-EF7A`.

## 3. Конверт копии

Комментарий внешнего ZIP: `"HRKEY1 " ‖ ASCII(канонический JSON)` (ключи по алфавиту, без пробелов), не длиннее 65 535 байт.

Запечатывание секрета копии на `pub` (ECIES-подобная схема, как получатели X25519 в age):

```
esk, epk = новая эфемерная пара X25519
shared   = X25519(esk, pub)
k        = HKDF-SHA256(ikm = shared, salt = epk ‖ pub, info = "homensai-rent/archive-secret/1", L = 32)   ; RFC 5869
ct       = ChaCha20-Poly1305(k).encrypt(nonce = 12 случайных байт, plaintext = секрет (44 байта ASCII),
                                         aad = "homensai-rent/archive-secret/1")                       ; 60 байт
```

| Поле | Тип | Значение |
|---|---|---|
| `v` | число | `1` |
| `mode` | строка | `generated` / `custom` / `pin` (или `none` — тогда других полей нет) |
| `kid` | строка | отпечаток `HR1-…` ключа хозяйства |
| `pub` | b64url(32) | открытый ключ хозяйства |
| `epk` | b64url(32) | эфемерный открытый ключ |
| `nonce` | b64url(12) | nonce ChaCha20-Poly1305 |
| `ct` | b64url(60) | запечатанный секрет копии |
| `wrapped` | объект | § 2 |
| `recovery` | массив, необязательно | `{"id": "RK-XXXX-XXXX", "sealed": {…}}` на каждый действующий ключ восстановления (до 3 бумажных + 10 аппаратных) |

Читатель ДОЛЖЕН считать «прежней копией без конверта» только комментарий без префикса `HRKEY1 `; префикс есть, а JSON не
разбирается, `v ≠ 1` или неизвестный `mode` — повреждение (`corrupt`).

## 4. Объект `sealed` — закрытый ключ хозяйства на ключ восстановления

```
seed      = HKDF-SHA256(ikm = ключ восстановления (16), salt = нет, info = "homensai-security/recovery-key/1", L = 32)
rsk, rpk  = X25519 с закрытым ключом seed
esk, epk  = новая эфемерная пара X25519
k         = HKDF-SHA256(ikm = X25519(esk, rpk), salt = epk ‖ rpk, info = "homensai-security/recovery-seal/1", L = 32)
ct        = ChaCha20-Poly1305(k).encrypt(nonce12, закрытый ключ хозяйства (32),
                                          aad = "homensai-rent/archive-identity-recovery/1" ‖ pub)       ; 48 байт
sealed    = {"v":1, "rpk":b64url, "epk":b64url, "nonce":b64url, "ct":b64url}
id        = "RK-" + XXXX + "-" + XXXX из первых 8 знаков HEX(SHA-256("homensai-security/recovery-id\x00" ‖ rpk)), верхний регистр
```

Растягивания (Argon2id) здесь нет: у ключа 128 бит случайности.

## 5. Открытие конверта (секрет копии)

1. Пустой ввод — `no_key`.
2. Ввод похож на ключ восстановления (после нормализации начинается с `RK1` или содержит `RS1`) — разобрать как ключ
   (§ 6) или две-три части (§ 6.2); ошибка формата (`recovery_format`) — пробовать как пароль, опечатка
   (`recovery_checksum`) и ошибки частей — вернуть код. Перебрать все `recovery[].sealed`,
   у которых `rpk` совпал; ни один не открылся — `recovery_wrong`.
3. Иначе — пароль/PIN: § 2 (`bad_password` при неверном теге).
4. `X25519(закрытый ключ хозяйства, epk)` → `k` как в § 3 → расшифровать `ct`; неверный тег — `corrupt`.
5. Полученные 44 байта — пароль внешнего ZIP AE-2 (`archive-format.md`).

## 6. Запись ключа восстановления и частей

Алфавит Crockford Base32 `0123456789ABCDEFGHJKMNPQRSTVWXYZ`. Кодирование: байты как целое big-endian, сдвинутое влево
до кратности 5 бит (нулевые хвостовые биты ДОЛЖНЫ быть нулями), знаки от старших бит. Нормализация ввода: верхний
регистр, удалить пробелы и `- _ . , ; :`, заменить `O→0`, `I→1`, `L→1`.

### 6.1 Ключ `RK1`

`RK1-` + 30 знаков группами по 5 от `ключ (16) ‖ SHA-256("homensai-security/rk/1" ‖ ключ)[0:2]` (144 бита + 6 нулевых).
Неверная длина или знак — `recovery_format`; контрольная сумма — `recovery_checksum`.

### 6.2 Части Шамира `RS1` (2 из 3)

- Разделение: pycryptodomex `Shamir.split(2, 3, ключ, ssss=False)` — поле GF(2^128) с многочленом
  `x^128 + x^7 + x^2 + x + 1`, элемент — целое из 16 байт big-endian (бит i — коэффициент x^i), точки `x = 1, 2, 3`,
  `f(0) = ключ`, второй коэффициент случайный.
- Метка набора — 2 случайных байта на выпуск (у наборов, выданных до ревью DR-recovery №1, — `SHA-256("homensai-security/rs-tag/1" ‖ ключ)[0:2]`; такие части читаются).
- Запись: `"RS1-" + N + "-"` + 35 знаков группами по 5 от `payload ‖ SHA-256("homensai-security/rs/1" ‖ payload)[0:2]`,
  где `payload = N (1 байт) ‖ метка (2) ‖ значение части (16)`.
- Сборка: любые две части с одной меткой; одна — `shares_needed`; разные метки или три части не на одной прямой —
  `shares_mismatch`. Собранный ключ проверяется не меткой, а расшифровкой `sealed` (`recovery_wrong`).

### 6.3 Ключ из аппаратного ключа (WebAuthn PRF)

`ключ восстановления = HKDF-SHA256(ikm = PRF-выход (32), salt = нет, info = "homensai-security/webauthn-prf/recovery/1", L = 16)`;
соль PRF у программы постоянная (`homensai-security/webauthn-prf/backup/1`, как её передаёт браузер — **уточнить**
точную кодировку соли в запросе `prf.eval`). Дальше — как обычный ключ восстановления (§ 4).

## 7. Пароль входа и PIN (для полноты)

Пароль входа в веб (`webauth/0003`): Argon2id `m=65536, t=3, p=4`, соль 16, ключ 32, пароль — NFKC → UTF-8, хранение
по столбцам (`argon_m`, `argon_t`, `argon_p`, `salt`, `derived_key`); схема базы требует `m ≥ 19456, t ≥ 2`. Прежний
`scrypt` (`N=2^15, r=8, p=1`) читается и перешифровывается при входе. PIN действий (уровни безопасности, `app/security/actions.py`) — запись PHC
`$argon2id$v=19$m=…,t=…,p=…$соль$хэш` (base64 без дополнения, NFKC). Вектора — `argon2id.json` (`phc`).
