# Изменения

## 0.4.0 — не выпущено (тег — по команде владельца)
Новая функция, обратно совместимая (минорная версия): вход по одноразовому коду из почты (решение Rent 28.10-344).
- `reset`: правила рядом со сбросом — `LOGIN_CODE_TTL` (10 минут), `LOGIN_CODE_DIGITS` (8), `LOGIN_CODE_ATTEMPTS` (5),
  `LOGIN_CODES_PER_HOUR` (3); `email_login_allowed` / `email_login_can_enable` (только при проверенной почте, по умолчанию
  выключено), `email_login_weakens` (почта без второго фактора), `new_login_code` (код, токен ссылки, токен окна браузера),
  `normalize_login_code`, `login_code_message` (что подписывает HMAC продукта: код привязан к своему запросу),
  `login_codes_rate_ok`, `login_code_state` (active/used/superseded/burned/expired), `login_code_verdict`, `mac_equal`.
  Код заменяет только пароль: при включённом ключе или Google Authenticator после кода нужен и он.
- `auth_errors`: `email_login_off`, `email_login_mail`, `email_login_code_wrong`, `email_login_expired`, `email_login_browser`,
  `email_login_rate` (в базе ошибок — SEC-AUTH-043…048, версия базы 1.6.0).
- `auth_texts`: письмо с кодом (`login_code_subject`, `login_code_body`), уведомление о входе (`tg_login_code`,
  `imp_login_code`, `imp_login_code_note`).
- `levels`: поле `LevelFacts.email_login_weak` (по умолчанию False) и мера уровня 3 `email_login_2fa`: вход по коду из почты
  без второго фактора не даёт уровень 3 и выше — мастер показывает эту меру как причину.

## 0.3.2 — не выпущено (тег — по команде владельца)
- `errors`: код `trustee_code_wrong` — «Код доверенного лица не подходит» (решение Rent 28.10-348; в базе ошибок
  HomenSAI/ERROR-DATABASE — `SEC-KEY-009`, версия базы 1.5.0). Продукт выдаёт его, когда код доступа доверенного лица
  на странице входа неверный, отозван или уже использован.
- `backup_keys.change_password`: уточнено описание — прежние копии открываются прежним паролем или ключом восстановления.
- Поведение функций и форматы не менялись.

## 0.3.1 — 15.11.2026
Исправления по независимому ревью перехода Rent на модуль (находки 3 и 8):
- `public_api.paper_input`: границы ключа и частей задаёт число строк (ключ — 2, часть — 3), а не префикс строки. Раньше вторая
  строка, случайно начинавшаяся с «RK1»/«RS1» (≈1 из 16 384 ключей, для частей ≈1 из 8192), считалась началом новой части и
  верный ключ отвергался с `recovery_checksum`.
- Вместо «·» (его нет на клавиатуре) строки листа принимаются и с пробелом, точкой или дефисом перед знаком (`codes.split_paper_line`);
  обычная запись и пароль по-прежнему не принимаются за лист.
- `codes`: `paper_groups`, `split_paper_line`, `PAPER_KEY_LINES`, `PAPER_SHARE_LINES`. Форматы на диске и на листе не менялись.

## 0.3.0 — 14.11.2026
Решение владельца 333 (8 предложений по безопасности; подключение к экранам продукта — после пилота):
- `codes`: бумажная запись ключа восстановления с контрольным знаком на каждой строке (`paper_lines`, `check_paper_line`, `from_paper`) — контрольный знак Luhn mod 32: любая одна ошибочная буква и строка на чужом месте ловятся всегда (знак из хэша ловил их лишь в 31 случае из 32, тест был нестабилен).
- `public_api.paper_input`: ввод ключа строками с бумажного листа; `recovery_from_input` принимает и их (ключ или две-три части).
- `sheet`: аварийный лист шире — место для пароля входа от руки, адрес программы, доверенное лицо.
- `trustee`: доверенное лицо с ожиданием (образец — Bitwarden Emergency Access): запрос, отказ, отзыв, доступ после срока.
- `backup_keys`: смена пароля копий отдельно от смены ключа (`change_password`, `rekey`).
- `backup_chain`: откат к последней доверенной копии (`last_trusted`).
- `restore_policy`: отбор устаревших сообщений после восстановления (`stale_after_restore`), проверка неизменяемости облачных копий (`object_lock_problem`).
- `errors`: коды `trustee_invalid`, `trustee_no_request`.
- Пакет помечен `py.typed` (PEP 561): mypy продукта проверяет вызовы модуля по его аннотациям.
