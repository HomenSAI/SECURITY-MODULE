# Изменения

## 0.6.0 — не выпущено (ветка `secx/levels-v2`; решения Rent 28.10-373, 374, 375)
Минорная версия: шкала уровней 0–6, перенос сохранённого состояния по маркеру, PIN 4–6 цифр, настройка печати месяца, предложение повысить уровень.
- `levels`: 7 уровней — 0 «Без защиты», 1 «Только PIN» (вход по паролю или PIN; 0 — только когда входа нет совсем), 2–6 — прежние 1–5; цепочка 2–6 накопительная и не требует уровня 1 (вход по паролю остаётся); `RECOMMENDED_LEVEL = 3`, `MAX_LEVEL = 6`; `LevelFacts.login_protected` (по умолчанию True) и `pin_login` (показ).
- `wizard`: `set_target` 0–6, `RISKY_LEVELS = (0, 1, 2)`, шаг `pin_login`, уровни шагов +1; `WizardState` пишет маркер `scale=7`; JSON без маркера — прежняя шкала: `target = max(target, 1) + 1` (прежний 0 → 2), шаг `pin_login` помечается «пропущен»; перенос идемпотентен.
- `actions`: `check_pin` принимает 4–6 цифр (прежние 4-значные PIN остаются верными); `Policy.seal_manual_without_pin` (по умолчанию False — только автопечать месяца).
- `upgrade` (новый, 28.10-375): `OfferState`, `schedule`, `due`, `decline`, `accept`, `set_period`, `offer(level, lang)`; периоды 14/30/60/90/180 дней, по умолчанию 30; на уровне 6 предложения нет; тексты рисков ru/uk для каждого уровня (`upgrade_texts`); ошибка `offer_period`.
- Правки по независимому ревью 17.11.2026 (docs/reviews/SEC_LEVELS_V2_REVIEW.md в Rent):
  - С1 `levels`: без входа по паролю или PIN уровень всегда 0 (уровни 2–6 требуют меры уровня 1); у `LevelFacts.login_protected` больше нет значения по умолчанию — вызывающий обязан передать факт.
  - С2 `wizard`: выбранный уровень пишется ключом `target_v2` (прежний `target` не пишется), маркер `scale=7` остаётся; нет `target_v2` и нет `scale` — прежняя шкала со сдвигом на 1. Откат на 0.5.0: она не знает `target_v2`, выбранный уровень теряется (мастер предложит рекомендуемый), но не искажается и не сдвигается повторно при возврате на 0.6.0; шаги сохраняются.
  - С3 `actions`: включение `seal_manual_without_pin` — ослабление (`lowering` даёт `seal_without_pin`, нужна галочка риска). Действие `month_seal` в `ACTIONS` не добавляется: печать месяца — в Rent (ветка perf-cold), из проекта убрано.
  - С4 `actions`: пауза после PIN-ошибок растёт — 10 минут после 5-й, затем вдвое за каждый круг из 5 ошибок (20, 40, 80 … до суток): `pin_pause_seconds`, `PIN_PAUSE_MAX_SECONDS`.
  - Н4 `wizard`: `WizardState.risk_acked` (ключ `risk_acked`): перенесённый прежний выбор 0/1, сделанный с галочкой риска, не просит галочку заново при повторном выборе деления 2; уход на другое деление подтверждение сбрасывает. Н3: тест — «широкие» цифры отклоняются `check_pin` и `verify_pin`. Н1: шаг `pin_login` в Rent считается выполненным, когда вход защищён паролем или PIN (мера уровня 1).
  - Н2 `upgrade.due`: дата отсчёта в будущем не скрывает предложение. Н5: в тексте риска потери PIN сказано, что сброс командой на компьютере доступен всякому, кто работает за ним.
- Совместимость: откат на 0.5.0 теряет выбранный уровень (ключ `target_v2` ей неизвестен), шаги и прочее сохраняются; повторного сдвига нет.

### Вход по почте: лимит писем (ветка `secx/email-rate`)
Новая функция, обратно совместимая (минорная версия): лимит писем с кодом входа — раздельные счётчики (решение Rent
28.10-366, Н1 ревью входа по почте: посторонний за 3 запроса закрывал владельцу вход по коду на час).
- `reset.login_codes_rate(sent, now, *, source, trusted=False) -> LoginRate` (`ok`, `reason` window/ceiling, `recent`,
  `important`); `reset.LoginCodeSent(at, source)`; константы `LOGIN_CODES_CEILING_HOUR` (10), `LOGIN_CODES_OWNER_RESERVE` (3).
- `reset.login_codes_rate_ok(sent, now, *, source=None, trusted=False)`: источник запроса передаётся в проверку; прежний
  вызов без источника — как в 0.4.0 (3 письма в час).
- `important.email_login_rate_item(rate, today, *, hrefs=None, lang="ru")`: строка «Важного» при исчерпании (без адресов,
  окон и кодов); `Hrefs.email_login` (по умолчанию `/security#email-login`).

Сборка: ruff по `src` и mypy strict чистые (E501 разрешён для модулей таблиц текстов, `pin_pause_seconds` возвращает `int`); полный pytest модуля зелёный, `scripts/build_security_help.py --check` без расхождений.
Ветки `secx/levels-v2` и `secx/email-rate` слиты в `secx/0.6.0` (конфликт был только в этом файле); `main` модуля не тронут, тег не создан.

## 0.5.0 — не выпущено (тег — по команде владельца)
- 16.11.2026: ветки `secx/rent-ui-docs` (0.3.2–0.3.3) и `secx/email-login` (0.4.0–0.5.0) влиты в `main` по порядку,
  без перезаписи истории; тег не создан (по команде владельца). Колесо собирается воспроизводимо (две сборки — один SHA-256).
Новая функция, обратно совместимая (минорная версия): код входа из почты — во фрагменте ссылки (решение Rent 28.10-352 п. 1, П3).
- `reset.login_code_link(page_url, link_token, code)`: ссылка для письма — токен ссылки в запросе, код во фрагменте «#…»
  (браузер фрагмент на сервер не отправляет; в журналы веб-сервера код не попадает).
- `reset.fragment_code(fragment)`: код из фрагмента (8 цифр) или None — те же правила, что у страницы показа кода.
- Хранение уточнено: продукт хранит только HMAC кода (`login_code_message`) и SHA-256 токенов; сам код — ни открыто,
  ни шифротекстом. Прежние продукты, хранившие шифротекст «для показа», переходят на фрагмент и стирают его.

## 0.3.0 — 14.11.2026
Решение владельца 333 (8 предложений по безопасности; подключение к экранам продукта — после пилота):
- `codes`: бумажная запись ключа восстановления с контрольным знаком на каждой строке (`paper_lines`, `check_paper_line`, `from_paper`) — контрольный знак Luhn mod 32: любая одна ошибочная буква и строка на чужом месте ловятся всегда (знак из хэша ловил их лишь в 31 случае из 32, тест был нестабилен).
- `public_api.paper_input`: ввод ключа строками с бумажного листа; `recovery_from_input` принимает и их (ключ или две-три части).
- `sheet`: аварийный лист шире — место для пароля входа от руки, адрес программы, доверенное лицо.
- `trustee`: доверенное лицо с ожиданием (образец — Bitwarden Emergency Access): запрос, отказ, отзыв, доступ после срока.
- `backup_keys`: смена пароля копий отдельно от смены ключа (`change_password`, `rekey`).
- `backup_chain`: откат к последней доверенной копии (`last_trusted`).
- `restore_policy`: отбор устаревших сообщений после восстановления (`stale_after_restore`), проверка неизменяемости облачных копий (`object_lock_problem`).
- `errors`: коды `trustee_invalid`, `trustee_no_request`.
- Пакет помечен `py.typed` (PEP 561): mypy продукта проверяет вызовы модуля по его аннотациям.
